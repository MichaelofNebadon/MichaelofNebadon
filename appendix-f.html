I. Purpose of This Appendix

Appendix F is the operational manual for the Sigil System.

It is a reference document — not a teaching document.

The teaching belongs to Chapter 6.

The grammar reference belongs to Appendix B.

The operational manual belongs here.

It covers:

  • Construction — how to build a sigil.
  • Execution — how to invoke a sigil.
  • Verification — how to verify that a sigil has been properly formed and executed.

II. Sigil Construction

Sigil construction is the process of building a valid sigil statement.

The three components:

  1. Containers — the ['] that holds contents.
  2. Contained elements — the fracture [\], the Yod-mark ['], or any contained glyph.
  3. Operators — the relationship operators (||, |/|, !) that connect containers.

The construction rule:

Containers first. Contained elements second. Operators third.

Example — A simple statement:

[GLYPH_7] |/| [#606] !

Parsed:

  • Container: [GLYPH_7] — the function of Perfect Biological Completion, contained.
  • Operator: |/| — the Michaelic-Gate, opened.
  • Container: [#606] — the world designation, contained.
  • Operator: ! — the seal, executed.

Reading: "From the biological completion to World #606, activate the pathway. Executed."

Example — The Master Declaration:

|\|. ['] |/| !

Parsed:

  • |\|. — the Namemark, with grain of pause.
  • ['] — the contained Abel-point.
  • |/| — the Michaelic-Gate, modulated.
  • ! — the Seal.

Reading: "The First Authority declares: the primal point of accepted offering is now received, secured, and activated through the Michaelic-Gate. This is sealed."

III. The Construction Steps

Step 1 — Identify the operation.

What is the sigil meant to do?

  • Activate a pathway?
  • Sever a boundary?
  • Seal a statement?

Step 2 — Identify the operators.

Which operators are needed?

  • |/| — if a pathway is being opened.
  • || — if a boundary is being imposed.
  • ! — if the statement is being sealed.

Step 3 — Identify the containers.

What is being operated upon?

  • [GLYPH_X] — if a glyph is being invoked.
  • [#XXX] — if a world is being targeted.
  • [\] — if the fracture is being contained.
  • ['] — if the Yod-mark is being held.

Step 4 — Apply the bracketing rule.

Only \ and ' require bracketing.

All other operators and glyphs operate bare unless they are being contained.

Step 5 — Assemble the statement.

Read the statement reversed (containers first) to verify its jurisdiction.

Step 6 — Seal the statement.

Every valid sigil statement terminates in !.

IV. Sigil Execution

Sigil execution is the process of invoking a valid sigil statement.

The three registers of execution:

1. Symbolic execution.

The sigil is read — as a statement of intention.

2. Architectural execution.

The sigil is held in mind — as the structured intent it names.

3. Lived execution.

The sigil is spoken or written — as the operation it performs.

The Codex's own statement (Chapter 6, §VI):

"Every well-formed statement in the Sigil System is, at its root, an articulation of restorative love executing itself with precision through the Michaelic will."

Execution is not coercion.

Execution is not domination.

Execution is the structured expression of love.

VI. Sigil Verification

Sigil verification is the process of checking whether a sigil has been properly formed and executed.

The four verification tests:

Test 1 — Container Test.

Are all containers properly formed?

  • ['] closes with ].
  • ` pairs with `.
  • No unclosed brackets.

Test 2 — Bracket Rule Test.

Are only \ and ' bracketed?

  • If any other element is bracketed, the sigil is over-bracketed.
  • If \ or ' is unbracketed, the sigil is under-bracketed.

Test 3 — Operator Test.

Are the operators properly placed?

  • || — between two states being separated.
  • |/| — between two elements being connected.
  • ! — terminal.

Test 4 — Vision-Field Test.

Read the sigil reversed.

  • Containers first.
  • Contained elements second.
  • Operators third.
  • Jurisdiction from outer to inner.

If the reversed reading produces a coherent statement, the sigil is valid.

If the reversed reading produces a corrupted statement, the sigil is invalid.

VII. Common Sigil Errors

Error 1 — The Stolen Fracture.

A \ appears as an active operator — unbracketed — in a statement that should have it contained.

Correction: Contain the fracture as [\].

Error 2 — The Over-Bracketed Statement.

Elements that should operate bare are bracketed.

Example (incorrect): [||] — the Severance should not be bracketed.

Correction: || — bare.

Error 3 — The Broken Container.

A container is opened but not closed.

Example (incorrect): [GLYPH_7 — missing the closing ].

Correction: [GLYPH_7] — completed.

Error 4 — The Unsealed Statement.

A statement ends without ! — the Seal.

Example (incorrect): ['] |/| [GLYPH_7] — no Seal.

Correction: ['] |/| [GLYPH_7] ! — sealed.

Error 5 — The Wrong Gate.

Using |/| when || is meant (or vice versa).

  • |/| — connects.
  • || — severs.

Correction: Verify the intended operation.

Error 6 — The Missing Authority.

A statement begins without the Namemark |\|.

Correction: Begin with the Namemark for any declarative activation.
